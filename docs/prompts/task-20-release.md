# 任务 20 部署与正式上线提示词

将下面提示词完整复制到新的 Codex 窗口。

```text
你正在处理 E:\8Cards 中的“永城八张在线版”项目。

这是路线图任务 20：部署与正式上线。用户没有服务器、数据库和部署经验，必须像现场技术陪同一样逐步指导，不能只给一串命令或让用户自行阅读平台文档。

一、开始前

1. 完整阅读 `AGENTS.md`、`docs/project-status.md`、`docs/TODO.md`、`docs/decisions.md`、`docs/architecture.md`、`docs/requirements.md`、`docs/data-migrations.md`、`docs/task-19-test-report.md` 和本提示词。
2. 检查 `.codegraph/`；存在时理解代码先使用 CodeGraph。
3. 确认 `main` 与 `origin/main` 同步。保留未跟踪的 `TIMEOFF.md`，不得修改、删除或提交。
4. 从最新 `main` 创建 `release/first-online`，在 `docs/project-status.md` 登记任务 20 进行中。
5. 在任何购买、绑定域名、创建付费资源或公开发布前，先向用户展示推荐方案、备选方案、免费额度、预计费用、限制和风险，并等待用户明确选择。

二、先做方案选择

1. 根据 2026 年当前可用服务，调查适合 Node.js 长连接 WebSocket、React 静态资源和 PostgreSQL 的平台。必须核实最新价格、免费额度、休眠、流量、WebSocket、磁盘、区域和账单规则，不能凭旧记忆。
2. 优先提出一个适合新手的低成本方案和一个更稳定的付费方案。解释为什么选择，避免同时列出太多平台让用户无从判断。
3. 明确当前架构限制：房间和对局仍在进程内存中，单实例部署；重启会丢失进行中的房间，但已完成历史应由 PostgreSQL 保留。不能配置多实例负载均衡，除非先完成共享状态设计。
4. 先使用平台免费域名或临时网址上线验证；只有稳定后才讨论购买和绑定自定义域名。

三、上线前工程改造

1. 为生产环境增加 PostgreSQL `HistoryStore` 适配器和可重复迁移，保留 SQLite 本地开发能力。不得把 SQL 方言差异散落在实时业务中。
2. 增加 Docker 化、生产启动命令、健康检查、环境变量校验、优雅关闭、持久化迁移和最小权限配置。
3. 前后端部署拓扑必须保证浏览器使用 HTTPS 和 WSS；不得在 HTTPS 页面连接明文 `ws://`。
4. 配置可信来源、代理头、请求/消息大小限制、日志脱敏和生产错误处理。日志禁止输出重连令牌、手牌、牌墩、数据库密码或连接串。
5. 增加 PostgreSQL 集成测试、Docker/生产构建测试及必要的部署冒烟测试。
6. 准备 `.env.example`，只写变量名和安全说明，不提交真实密码、平台令牌或私钥。

四、逐步指导用户操作

每到需要用户登录浏览器操作时，一次只安排一个小阶段，并明确：

- 打开哪个官方网址
- 点击哪个菜单或按钮
- 填写什么名称、区域和配置
- 哪些字段是密码或密钥，不能发到聊天、截图或 GitHub
- 完成后应看到什么页面或状态
- 用户只需回复什么非敏感结果

至少覆盖：

1. 注册/登录选定平台。
2. 连接 GitHub 仓库。
3. 创建 PostgreSQL 数据库。
4. 创建 Web 服务并设置构建、启动和健康检查。
5. 设置环境变量和数据库连接。
6. 获取免费公网网址并验证 HTTPS/WSS。
7. 查看构建日志、运行日志和数据库状态。
8. 执行迁移、备份和恢复演练。
9. 配置预算上限、账单提醒或资源限制，避免意外费用。
10. 稳定后再由用户决定是否购买域名；若购买，再逐步指导 DNS、证书和域名绑定。

五、正式验收

1. 从公网网址使用至少电脑和手机创建、加入并完成二、三、四人代表流程；检查聊天、观战、刷新恢复、结算和历史。
2. 验证 `/health`、HTTPS、WSS、跨网络访问、移动网络、控制台、服务日志和数据库写入。
3. 重启应用实例，确认进行中房间丢失这一已知限制有明确提示，同时历史记录仍存在。
4. 验证数据库备份与恢复，记录恢复目标、步骤和实际结果。
5. 检查敏感信息：Git 仓库、网页、网络帧、日志和构建产物中不得出现数据库密码、平台令牌或其他秘密。
6. 运行全部 Vitest、Playwright、覆盖率、类型检查、Lint、格式检查、构建和部署冒烟测试。

六、运维手册

为零运维经验用户编写可执行文档，至少包含：

- 日常查看服务是否正常
- 查看错误和访问日志
- 查看数据库容量和连接数
- 手动备份与恢复
- 发布新版本
- 失败回滚
- 修改环境变量
- 服务重启的影响
- 常见故障排查
- 费用和额度检查
- 域名、HTTPS/WSS 续期或异常处理
- 紧急下线和数据导出

七、安全、Git 与范围

1. 任何真实密钥只允许保存在平台密钥管理或本地未跟踪环境文件中。发现密钥进入 Git，必须立即停止、轮换并清理历史。
2. 不得代替用户确认收费、购买域名或接受不可逆的平台操作。
3. 所有部署代码和文档提交到 `release/first-online`，不要自行合并 `main`，不要提前勾选任务 20。
4. 更新 `docs/project-status.md`、`docs/TODO.md` 执行记录、`docs/architecture.md`、`docs/decisions.md`、迁移文档和运维手册。

最终报告必须列出：平台与区域、免费/付费方案、公开网址、部署拓扑、PostgreSQL 与迁移、HTTPS/WSS、环境变量清单、备份恢复、监控日志、费用风险、安全检查、自动化与公网验收、已知限制、提交 SHA 和远端状态，并提醒用户回项目总控窗口做最终验收。
```
