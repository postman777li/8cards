   - 本局名次；
   - 本局基础分；
   - 本局倍率；
   - 倍率后的本局分数增减；
   - 结算后的累计总分；
   - 本局胜/负/未决或队伍结果；
   - 必要的安全结算原因。
3. 客户端不得自行重算名次、倍率或分数。数据必须来自权威结算，并随刷新、断线恢复和继续投票恢复。
4. 单局历史与整场汇总继续幂等；不得因为新增展示数据重复计分或重复持久化。
5. 不公开手牌、牌墩顺序、触发者私有牌或其他隐藏信息。

### 4.2 名次语义

1. 普通出完流程已有完整 `finishOrder`，二人显示 1/2，三人显示 1/2/3，四人显示 1/2/3/4。
2. 普通四人局仍按现有规则计算“首位出完者所在队伍分 + 剩余三人排名分”；页面同时展示真实个人出完名次和权威本局分数，不得混淆队伍胜负与个人名次。
3. 因憋王或主动退出提前结束时，没有发生完整先后顺序，不得伪造唯一名次：
   - 二人：胜者第 1、负者第 2；
   - 三人憋王：两名非失败者并列第 1，失败者第 3；
   - 四人团队憋王/退出：获胜队两人并列第 1，失败队两人并列第 3；
   - 若其他已有结算路径属于未决，继续按权威结果使用标准竞赛排名并明确显示“未决”。
4. 标准并列排名采用 `1, 1, 3, 4` 这种竞赛排名语义。

### 4.3 单局结算界面

1. 单局结束弹窗必须像最终排行榜一样有完整的金银铜名次视觉：第一名金色圆章/奖牌，第二名银色，第三名铜色，第四名保持清楚一致。
2. 每一行清楚显示头像、昵称、本局名次、本局分数增减、倍率和累计总分。
3. 本局增减必须带正负号；基础分、倍率和最终增减的关系可快速看懂，例如 `基础 +1 × 3 倍 = 本局 +3`。
4. 四人队伍关系、憋王/退出原因和并列排名需要直观说明，但不能堆成大段文字。
5. 继续投票位于单局结果下方，视觉上不得抢走排名主体；等待人数和本人选择仍要清晰。
6. 桌面、手机横屏、手机竖屏均可完整查看；允许弹窗内部纵向滚动，但禁止页面级横向滚动或关键按钮被截断。
7. 排名逐行揭晓、分数计数变化和奖牌出现应有克制动效及对应音效；减少动态模式下安全降级。

## 七、重构憋王规则（用户最新确认，优先级最高）

旧规则“手牌一变成非空纯王便立即判负”作废。新规则如下，必须先更新 `docs/game-rules.md` 和 `docs/decisions.md`，再实现二、三、四人状态机。

### 7.1 唯一触发时机

1. 玩家手牌只剩一个或多个王时，不立即判负。
2. 王仍可在该玩家担任防守方、需要压牌时正常使用；只要合法压住来牌，就可以继续游戏，甚至可以正常出完并获得名次。
3. 只有同时满足以下全部条件才触发憋王：
   - 新一轮桌面为空；
   - 轮到该玩家担任这一轮的主进攻方；
   - 该玩家必须打出本轮第一张进攻牌；
   - 其非空手牌全部为王；
   - 因王不能作为进攻牌，玩家没有合法首攻牌。
4. 这时由服务端立即判定 `stuck-with-jokers`，不等待玩家点击非法按钮，也不让超时逻辑报普通错误。
5. 如果玩家只是第二进攻者/跟牌者，手里只有王不触发憋王；其可以按规则过牌，直到未来真正轮到其成为主进攻方时再判断。
6. 如果玩家是防守方且只剩王，可以合法压牌；不能因为动作前后存在纯王手牌而提前判负。
7. 如果玩家有“两张牌：一张王 + 一张普通牌”，打出普通牌后只剩王，不立即判负。必须让游戏继续；若之后作为防守方能用王压牌，就正常使用。只有未来轮到其空桌主攻且仍只剩王时才憋王。
8. 一个或多个王采用相同规则。

### 7.2 各人数模式

1. 二人：触发者本人判负，对手获胜。
2. 三人：触发者本人判负，另外两人按现有三人憋王计分/并列排名语义结算。
3. 四人原始团队阶段：触发者所在原队伍立即判负，另一队获胜。
4. 四人已有玩家出完、权威状态降为三人或二人后，仍必须保留原四人队伍关系并按项目已确认的四人憋王结算，不得因状态模式降级丢失队伍。
5. 憋王仍是提前终止单局的例外，不进入普通逐个淘汰流程，但必须生成第四节要求的权威单局并列名次和分数数据。

### 7.3 必测边界

至少新增：

- 二/三/四人玩家打出最后一张普通进攻牌后只剩王，不立即失败；
- 只剩王的玩家作为防守方合法用王压牌并出完；
- 只剩王的玩家作为第二进攻者可以过牌且不失败；
- 防守成功或收牌结算后，纯王玩家成为下一轮空桌主攻时立即失败；
- 初始/人工状态中空桌主攻只有一个王或大小王时稳定失败；
- 牌墩仍有牌时补牌可能解除纯王状态，不得提前失败；
- 主 2 换明牌造成纯王手牌时，若不是强制首攻时机不得失败；
- 四人团队阶段及降为三/二人后的原队伍归属；
- 超时回调遇到纯王主攻时走权威憋王结算，不尝试选择不存在的普通牌；
- 随机整局模拟、牌张守恒和确定性复跑继续通过。

## 八、完整逐张发牌与补牌动效

任务 22 的简单抽牌轨迹仍不够。必须实现肉眼明确可见的一张一张发牌/补牌演出。

### 8.1 开局发牌

1. 开局不能直接让每名玩家瞬间显示 8 张牌。
2. 从中央/牌墩位置按权威逆时针发牌顺序，一张一张飞向每个玩家座位，循环进行直至每人 8 张。
3. 对本人，牌飞到手牌区后逐张加入并最终收敛到权威排序；对其他玩家只显示牌背及公开数量增长，绝不展示牌面。
4. 明牌抽取、主花色确定和明牌落位要有独立但连贯的表现，不得改变真实发牌规则。
5. 发牌节奏应有层次、不卡顿；可合理压缩持续时间，但必须明显表现“逐张轮流发”，不能一次飞八张或只改变数字。

### 8.2 后续补牌

1. 每轮结算后严格按服务端权威补牌顺序，从本轮主进攻方开始沿逆时针座次逐玩家补至 8 张。
2. 每一张牌都从牌墩单独飞向对应座位；同一玩家补多张也必须逐张表现，而不是一个标记写 `+3`。
3. 本人新牌逐张进入手牌并最终排序；其他玩家只显示牌背。
4. 牌墩厚度和剩余张数随每张动画同步变化并最终与最新权威快照一致。
5. 牌墩中途耗尽时自然停止并显示空牌墩状态。

### 8.3 权威时序与恢复

1. 发牌、彩蛋提示及开局演出不得偷走玩家的实际操作时间。演出未完成时不能让服务端回合倒计时在后台悄悄减少，也不能允许客户端抢先提交游戏动作。
2. 请设计最小、明确的服务端权威展示阶段或公开 `readyAt/dealEndsAt` 边界，使所有玩家看到一致节奏，回合截止时间在可操作后才开始。
3. 不得用客户端任意延迟来决定游戏合法性；服务端仍是唯一权威。
4. 刷新、断线恢复或较晚加入观战时，不重放完整过期发牌队列，直接收敛到当前权威状态；如果仍处于演出窗口，则从安全的当前进度恢复。
5. 快速状态、后台标签页、低性能设备和网络抖动不得留下幽灵牌、错误牌数或重复音效。
6. `prefers-reduced-motion` 或“减弱动画”开启时，改为快速逐张淡入/计数过渡，但仍保留清楚的发牌顺序和最终状态。
