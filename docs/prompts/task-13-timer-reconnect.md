这是路线图任务 13：倒计时和断线重连。本窗口只能完成任务 13，不得提前实现任务 14 或后续功能。

一 开始前必须完成

1. 完整阅读 `AGENTS.md`、README、`docs/project-status.md`、`docs/TODO.md`、`docs/decisions.md`、`docs/architecture.md`、`docs/requirements.md`、`docs/game-rules.md`、本提示词，以及 `packages/shared`、`packages/game-engine`、`apps/server` 的相关源码和测试。
2. 检查 `.codegraph/`；存在则理解代码时先用 CodeGraph，不存在则跳过。
3. 确认 `main` 干净并与 `origin/main` 同步，从最新 `main` 创建 `feature/timer-reconnect`。
4. 开始前在 `docs/project-status.md` 登记任务 13 正在进行，并向用户说明服务器计时器、超时动作、断线状态、令牌恢复、连接替换、版本协调和测试方案。
5. 遇到未提交的他人改动不得覆盖；发现产品或规则歧义不得静默猜测。

二 目标和边界

在任务 12 的权威 WebSocket 服务上实现默认 20 秒回合倒计时，以及玩家 socket 断开后保留座位、使用重连令牌恢复同一身份和完整私有状态。

已确认超时规则：进攻机会超时自动过牌；防守机会超时自动收牌。超时动作由服务器权威执行，和玩家主动动作一样推进引擎、实时版本及状态广播。

本任务不实现网页 UI、聊天、观战、战绩、数据库或跨进程恢复。第一版掉线座位在当前服务器进程存活期间持续保留，不自动踢出，也不自行设定未确认的保留分钟数。

三 可注入时钟与调度器

1. 不要把 `Date.now`、`setTimeout` 散落在业务逻辑中。定义窄的时钟/调度接口，可注入当前时间、安排单次任务和取消任务。
2. 生产默认实现使用系统时间与 Node 定时器；测试使用虚拟时间或确定性假时钟，不得真实等待 20 秒。
3. 每个已开始且未结束的房间最多只有一个有效回合计时器。
4. 每次安排计时保存不可复用的 generation。旧回调即使因竞争在取消后触发，也必须检测 generation 和期望实时版本后退出。
5. 服务关闭、游戏结束或房间运行态销毁时必须取消计时器，不留下句柄或悬挂进程。

四 倒计时语义

1. 游戏开局成功并广播初始游戏状态时，立即为当前行动机会设置 20 秒期限。
2. `turnDeadline` 是带时区 ISO 时间戳，等于服务器当前时间加房间配置的 20 秒，并通过共享 schema。
3. 每个成功消耗当前行动机会的动作后重新开始完整 20 秒：出牌、压牌、过牌、收牌及其造成的新回合。
4. `exchange-trump-two` 不消耗行动机会，成功交换后实时状态更新，但不得重置截止时间。
5. 非法、重复、过期、乱序请求和协议错误不得改变截止时间或 timer generation。
6. 等待房和已结束游戏的 deadline 为 null；同一版本的所有玩家看到完全相同的 deadline。

五 超时自动动作

1. 到期时重新核对房间、游戏、generation、实时版本、阶段和当前 actor。
2. `awaiting-attack`：以当前 actor 执行权威 `pass`。
3. `awaiting-defense`：以当前 defender 执行权威 `take/collect`。
4. 自动动作必须复用客户端动作的引擎映射、原子替换、版本递增、投影和广播路径，避免两套规则。
5. 自动动作不伪造 requestId 或 response，只广播新状态。
6. 玩家动作与超时临界竞争只能一个成功：先提交者改变 generation/version，后到者退出或收到过期错误。
7. 自动动作导致终局时取消 timer；真正内部异常必须受控处理，不能高速重试或形成未处理异常。

六 断线标记与座位保留

1. socket 关闭时，仅当它仍是该玩家当前有效 socket，才调用 RoomService 标记 disconnected；被新连接替换的旧 socket 关闭不能误伤新会话。
2. 断线不离房、不释放座位、不转移房主、不删除权威游戏状态。
3. connection 变为 disconnected，实时公开版本恰好 +1，并广播其他在线玩家。
4. 已开始游戏中 RoomService 版本和实时版本已经分离：RoomService 调用使用 room snapshot 自己的版本；实时版本只能从当前实时值 +1，绝不能倒退。
5. 等待房掉线同样保留座位和房主，不设置自动清退。
6. 掉线玩家轮到时倒计时继续，并执行自动过牌或收牌。

七 恢复协议与连接替换

1. 在共享客户端协议新增严格 `session.resume` 请求：protocolVersion、requestId、actionSequence、roomId、playerId、reconnectToken。
2. 只允许未绑定身份的新连接以序号 1 恢复。
3. 调用 RoomService `restoreSession` 验证并旋转令牌。成功后绑定新 socket，发送 `response.ok`、新 `session.established` 和最新本人 `state.player`，并向其他在线玩家广播 online 状态。
4. 旧令牌立即失效；错误房间、玩家或令牌统一返回 `UNAUTHORIZED`。
5. 如果旧 socket 仍存在，必须先原子替换当前 socket 映射，再用明确关闭码关闭旧 socket。旧 socket 不能再行动，其 close 回调不能标记新连接掉线。
6. 新连接序号重新从 1 开始，恢复成功后下一请求为 2。
7. 完全相同恢复请求在同一 socket 重发不得二次旋转令牌。应缓存并重放同一组单播结果，使网络重试仍能拿到同一个新令牌。
8. 令牌不得写入日志、公共广播、其他玩家消息或状态快照。

八 版本协调

1. 客户端只看到单调实时 stateVersion；引擎 version 与 RoomService version 均为内部值。
2. 主动游戏动作、超时动作、公开断线、从 disconnected 恢复 online 各使实时版本恰好 +1。
3. 在线玩家仅旋转私有令牌时不增加公开实时版本，但必须持久化。
4. 客户端 expectedStateVersion 校验实时版本；RoomService 操作使用 snapshot 房间版本。
5. 外层事件版本、PlayerView.public.stateVersion 和 deadline 必须一致。

九 投影与隐藏信息

1. 投影接收当前权威 deadline，不得每次发送时重新计算。
2. 同次广播给不同玩家时复用完全相同的 deadline。
3. 重连者只收到自己的手牌；任何其他连接不得收到该玩家手牌或令牌。
4. 断线、恢复、超时和终局状态全部经共享 schema 复验后发送。

十 必须覆盖的测试

1. 虚拟时钟证明开局 deadline 恰为 now + 20 秒，所有玩家一致，无真实等待。
2. 二人、三人、四人进攻超时自动 pass，版本和游标正确。
3. 防守超时在未压牌及存在历史已压牌时自动 collect，桌面、收牌和角色正确。
4. 玩家及时动作使旧 timer 失效并创建新 timer；强制触发旧回调不能二次改变状态。
5. 主 2 交换、非法、重复、乱序和 stale 请求不重置 deadline。
6. 自动动作与玩家动作竞争只能执行一个；终局后推进时间不再广播。
7. 等待房及对局中断线均保留座位、房主、手牌和权威状态，并广播 disconnected。
8. 掉线玩家轮到时仍会超时自动动作。
9. 正确令牌恢复并旋转，返回本人当前手牌；旧令牌重放和错误凭证统一拒绝。
10. online 令牌旋转不虚增公开版本；disconnected → online 恰好 +1。
11. 双连接替换后旧连接关闭且不能行动，旧 close 不误标掉线。
12. 同一恢复请求重试不二次旋转，仍返回同一新凭证。
13. 二、三、四人各完成一次“断线 → 状态或计时推进 → 恢复 → 私有状态同步”的真实 WebSocket 流程。
14. 原始消息继续扫描其他手牌、牌墩、令牌摘要和其他人的令牌泄漏。
15. 现有 195 项测试、规则覆盖率和 `/health` 全部继续通过。
