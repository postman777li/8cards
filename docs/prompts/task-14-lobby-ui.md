```text
你正在处理 E:\8Cards 中的“永城八张在线版”项目。

这是路线图任务 14：首页与创建加入房间。本窗口只能完成任务 14，不得提前实现任务 15 或后续功能。

一、开始前必须完成

1. 完整阅读 `AGENTS.md`、README、`docs/project-status.md`、`docs/TODO.md`、`docs/decisions.md`、`docs/architecture.md`、`docs/requirements.md`、`docs/game-rules.md`、本提示词，以及 `apps/web`、`packages/ui`、`packages/shared`、`apps/server` 中与大厅和实时协议相关的源码与测试。
2. 检查 `.codegraph/`；存在则理解代码时先用 CodeGraph，不存在则跳过。
3. 确认 `main` 干净并与 `origin/main` 同步，从最新 `main` 创建 `feature/lobby-ui`。
4. 开始前在 `docs/project-status.md` 登记任务 14 正在进行，并先说明页面结构、真实 WebSocket 接入、访客身份保存、响应式适配和测试方案。
5. 不得覆盖其他窗口的未提交改动；发现需求或协议歧义必须记录并向用户确认，不得静默猜测。

二、目标

用任务 04 已建立的“中原夜宴”原创设计系统完成正式质量的网页入口流程，让电脑和手机浏览器用户能够：

- 输入并保存昵称；
- 创建带自定义房间名称的房间；
- 使用随机短码加入房间；
- 从包含房间码的分享链接进入加入流程；
- 打开基础设置页面并保存本地偏好；
- 看清连接中、成功、失败、断线等状态。

创建和加入必须连接任务 11–13 的真实 `/ws` 协议，不能用假数据代替成功流程。成功后只需进入一个明确的“已进入房间/等待任务 15”占位状态，不实现等待房座位系统。

三、产品与交互要求

1. 首页应清楚展示游戏名称、简短说明、昵称输入、创建房间和加入房间入口；视觉完整，不能像工程演示页。
2. 创建房间至少包含房间名称和人数模式（二、三、四人）。协议中已有的观战、聊天和 20 秒倒计时配置按当前产品默认值发送；不要在本任务扩展未确认的高级设置。
3. 加入房间接受协议规定的短码，自动去除首尾空格并以协议允许的方式规范大小写；错误信息必须友好且保留服务端错误含义。
4. 分享链接从 URL 查询参数读取房间码并预填加入表单；生成/复制分享链接时不得包含重连令牌或其他秘密。
5. 昵称与非敏感设置保存在当前浏览器。重连令牌如需为后续任务保留，必须按房间/玩家隔离存储，不得进入 URL、日志或可见页面。
6. 设置页只实现本地界面偏好，例如音效开关、背景音乐开关、动画降级；没有真实音频素材时只保存设置，不伪装已播放音频。
7. 所有提交按钮具有禁用、加载、防重复提交和错误恢复状态；键盘回车可提交，焦点样式清晰。
8. 支持桌面和手机浏览器；手机竖屏首页与表单可正常使用，横屏也不能溢出。遵守减弱动画偏好。
9. 保持任务 04 的原创视觉方向，不复制腾讯名称、商标、美术、音频、字体或逐像素界面。

四、网络与状态边界

1. 建立窄的网页实时客户端层，使用 `@8cards/shared` schema 校验服务端消息；不要在 React 组件中散落原始 WebSocket 解析。
2. 开发环境 WebSocket 地址应由当前页面协议/主机或明确的 Vite 环境变量安全推导，支持未来 HTTPS/WSS 部署；不得硬编码某台电脑地址。
3. 创建使用 `room.create`，加入使用 `room.join`，每条连接从 actionSequence 1 开始，并正确关联 requestId、`response.ok/error`、`session.established` 和 `state.player`。
4. 只在收到完整成功结果后进入成功状态并保存凭证。失败、关闭或 schema 无效时不得留下半成功身份。
5. 清理组件卸载或流程替换产生的 socket、监听器和超时；不得形成重复连接或重复提交。
6. 任务 14 不实现 `session.resume` 自动恢复流程，但保存任务 13 返回的本人凭证，供任务 15/后续接入；不要自行设计第二套身份协议。

五、范围限制

本任务不实现：等待房玩家列表、座位、准备、房主设置、开始游戏、真实牌桌、出牌、聊天、观战、战绩、数据库或部署。这些属于任务 15–20。

允许修改 `apps/web`、必要的 `packages/ui` 共享组件、相关测试和项目文档。除非发现经过测试证明的协议阻断问题，不修改服务端、游戏引擎或游戏规则；若存在阻断，先报告总控。

六、测试与验收

至少覆盖：

1. 昵称、房间名称和短码的必填、边界与友好错误。
2. 创建/加入请求结构、动作序号和请求关联正确。
3. 服务端成功后保存非敏感身份与本人凭证并进入成功占位状态。
4. 服务端业务错误、连接失败、异常消息和断线时界面可恢复。
5. 分享链接预填短码，复制内容不含令牌。
6. 防重复提交和组件卸载清理连接。
7. 本地设置保存并在刷新后恢复。
8. 桌面、手机竖屏和手机横屏关键布局无水平溢出、遮挡或不可点击元素。
9. 现有服务端、协议、规则引擎测试全部继续通过。

运行并报告：`pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm test`、`pnpm test:coverage`、`pnpm build` 和 `git diff --check`。

实际启动网页和服务端，用真实浏览器流程验证创建与加入；至少检查一个桌面尺寸、一个手机竖屏尺寸和一个手机横屏尺寸，并保存仓库外验收截图。确认 `/health` 正常、WebSocket 可用、浏览器控制台无错误、页面无明显布局问题。
```
