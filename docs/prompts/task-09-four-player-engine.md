二 本任务目标

在 `packages/game-engine` 中复用任务 06 至 08 已验证的卡牌、攻防、多人游标和结算规则，实现纯函数、确定性、服务端权威的四人二对二状态机。

四人模式固定为对面座位组队。每轮只有一名防守方；防守方的对家完全旁观，另一队的两名玩家按逆时针游标轮流进攻。

三 对家与座次

1. 状态接收严格按逆时针排列的四名玩家数组，例如 `A → B → C → D`。
2. 对面座位组队：
   - A 与 C 一队。
   - B 与 D 一队。
   - 一般化为座位 0/2 与座位 1/3。
3. 任务 06 的 `firstDefender` 是首位防守方。
4. 主进攻方是防守方在座次中的前一位，其逆时针下一位正好是防守方。
5. 示例中 B 防守时：
   - A 是主进攻方并获得第一次进攻机会。
   - C 是另一名有效进攻者。
   - D 是防守方 B 的对家，本轮完全旁观。
6. 防守方对家不能进攻、不能过牌占用进攻机会、不能帮忙压牌，也不能替防守方收牌。

四 必须复用的既有规则

以下规则应复用或提取任务 07、08 已验证的细粒度逻辑，不得另写一套含义不同的版本：

- 首攻与跟牌不能使用王。
- 后续跟牌只能使用桌面普通牌已经出现的点数。
- 防守普通牌、主牌和王的压牌关系。
- 防守方可在未压牌或已经压住一张/多张后随时收整桌牌。
- 所有有效进攻者共享实时累计进攻数量限制。
- 连续过牌、合法进攻后清零连续过牌数。
- 从结算前主进攻方开始沿完整逆时针座次补牌。
- 主 2 任意时间交换底牌且不消耗当前行动机会。
- 不可变原子转换、稳定错误码、状态版本和 54 张牌守恒。

如需提取二人、三人、四人公共内部辅助函数，必须保持任务 07 和 08 的公共 API 与全部既有行为不变。

五 双进攻者游标与连续过牌

1. 本轮由主进攻方先获得进攻机会。
2. 当前进攻者成功出牌并由防守方压住后，游标沿逆时针座次移动到另一名有效进攻者，同时跳过防守方和防守方对家。
3. 过牌只放弃当前这一次机会，游标移动到另一名有效进攻者。
4. 任意有效进攻者成功出牌后，连续过牌数清零；之前过牌者之后仍可重新跟牌。
5. 只有两名有效进攻者在中间无人重新出牌的情况下连续过牌，才判定防守成功。
6. 防守方和防守方对家尝试进攻或过牌必须被拒绝；行动权不能由客户端点击速度决定。

六 防守与实时数量限制

1. 每次进攻后只有当前防守方能压牌或收牌。
2. 防守方对家不得压牌，即使其持有合法大牌或王。
3. 防守方成功压牌后，行动机会交给进攻游标指定的另一名有效进攻者。
4. 防守方可在待压牌阶段或所有桌面进攻牌已压住、当前轮到进攻者时收牌；收牌权限独立于普通进攻游标，但桌面必须非空。
5. 两名有效进攻者共用同一累计进攻数，并共同受防守方当前实时剩余手牌数限制。
6. 防守方从 8 张开始并连续压牌时，两名进攻者合计最多只能让其成功防守 4 张；第 5 张进攻被拒绝。

七 防守成功、收牌与下一轮

使用统一逆时针座次 `A → B → C → D`，并以 A 主攻 B 为示例：

1. 防守成功：
   - 桌面牌进入弃牌区。
   - 原防守方 B 成为下一轮主进攻方。
   - B 进攻其逆时针下一位 C。
   - 新一轮 C 的对家 A 旁观；B 与 D 是有效进攻者。
2. 防守方收牌：
   - 桌面所有攻防牌进入 B 的手牌。
   - B 的下一次进攻回合被跳过。
   - 由 B 的逆时针下一位 C 成为下一轮主进攻方，进攻再下一位 D。
   - 新一轮 D 的对家 B 旁观；C 与 A 是有效进攻者。
3. 每轮结算后重置桌面、引牌点数、累计进攻数和连续过牌数。
4. 补牌发生在角色切换前的结算中，并始终使用结算前的原主进攻方作为起点。

八 四人补牌顺序

1. 无论防守成功还是收牌，都从本轮原主进攻方开始，沿完整四人逆时针座次补牌。
2. A 主攻 B 时，补牌固定为 A、B、C、D；不能按队伍或进攻阵营改成 A、C、B、D。
3. 防守方对家虽然本轮旁观，但仍在自己的座次轮到时正常补牌。
4. 少于 8 张补至 8 张，达到或超过 8 张不抽；牌墩中途耗尽立即停止。
5. 测试必须使用短牌墩证明 A、B、C、D 的先后顺序会真实影响拿到哪张牌。

九 团队终局与憋王

1. 任意玩家手牌清空时，其所在整个队伍立即获胜，对局结束。
2. 任意玩家手牌非空且只剩一个或多个王时，其所在整个队伍立即判负，另一队获胜。
3. 结果应至少记录：
   - 获胜队伍及两名成员。
   - 失败队伍及两名成员。
   - 触发终局的玩家。
   - 原因：某队员出完手牌，或某队员憋王。
4. 憋王判负检查优先于空手获胜；空手本身不属于憋王。
5. 每次任何玩家手牌变化后都检查终局。
6. 多名玩家在同一原子转换同时憋王的优先级尚未确认；避免引入会同时减少多人手牌的批量动作。若结构上仍可能发生，使用稳定座次扫描并明确记录为任务 10 待复核，不得声称是最终规则。
7. 终局后拒绝所有普通动作。

十 主 2 交换

1. 四名玩家中任意持有者都可在未终局、牌墩非空且尚未交换时执行。
2. 不要求持有者是当前行动者；防守方对家即使正在旁观也可以交换，因为用户确认主 2 可在任意时间交换。
3. 交换不改变阶段、主进攻方、防守方、进攻游标、连续过牌数、队伍或主牌花色。
4. 继续保持整局一次语义，并覆盖主攻、另一进攻者、防守方和旁观对家四种身份。

十一 建议状态与公共 API

1. 提供清晰的 `FourPlayerState`、`FourPlayerAction`、团队结果、稳定错误类型、初始化函数、动作应用函数和不变量断言。
2. 状态至少包含：
   - 四人逆时针座次与两组对家关系。
   - 四手权威手牌、牌墩、弃牌区、底牌和主牌花色。
   - 本轮主进攻方、防守方、防守方对家、两名有效进攻者。
   - 当前进攻游标或当前行动者。
   - 桌面攻防牌对、引牌点数、累计进攻数、连续过牌数。
   - 主 2 交换标记、状态版本、阶段和终局结果。
3. 从 `@8cards/game-engine` 根入口导出稳定四人 API。
4. 不得导出能绕过不变量或直接修改权威状态的危险工具。

十二 必须覆盖的自动化测试

1. 队伍与初始化：
   - 验证座位 0/2、1/3 分组。
   - 四种首位防守方分别映射到正确主攻、另一进攻者、防守方对家和第一游标。
   - 非四人、重复玩家、损坏牌组或不一致初始状态被拒绝。
2. 行动权限：
   - 两名有效进攻者都能按游标出牌和过牌。
   - 防守方不能进攻，防守方对家不能进攻、过牌、压牌或收牌。
   - 防守方是唯一可压牌和收牌者。
3. 游标与连续过牌：
   - A 攻 B 并被压后轮到 C，C 攻击并被压后回到 A。
   - A 过、C 过完成防守成功。
   - A 过、C 出牌并被压后，A 能重新获得机会。
4. 出牌与压牌：
   - 两名进攻者共享桌面引牌点数和累计数量限制。
   - 王进攻、未出现点数、非法防守、错误手牌均被拒绝。
   - 防守牌贡献普通点数，王不贡献点数。
5. 收牌：
   - 防守方未压牌、压住一张、压住多张后都可收整桌牌。
   - 收牌后正确跳过防守方，由下一座主攻再下一座防守。
6. 补牌：
   - A 主攻 B 时，防守成功与收牌都严格按 A、B、C、D 补牌。
   - 旁观对家 D 正常参与补牌。
   - 已达到或超过 8 张跳过，短牌墩按座次耗尽。
7. 下一轮角色：
   - A 攻 B，B 防守成功后由 B 攻 C，B/D 为进攻队，A 旁观。
   - A 攻 B，B 收牌后由 C 攻 D，A/C 为进攻队，B 旁观。
8. 团队终局：
   - 四名玩家分别覆盖出完牌时其队伍获胜。
   - 四名玩家分别覆盖憋王时其队伍失败、另一队获胜。
   - 结果成员、触发者和原因正确。
9. 主 2 与不变量：
   - 四种身份都可任意时间交换且不改变游标。
   - 每次成功动作后完整 54 张牌无重复、无遗漏。
   - 每次非法动作后输入状态完全不变。
10. 至少实现一个包含 A、C 双进攻者、连续过牌、补牌和下一轮角色变化的完整流程测试。
11. 任务 07 的二人测试和任务 08 的三人测试必须全部继续通过。
