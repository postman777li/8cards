这是路线图任务 19：全系统测试与实际试玩。本窗口只负责测试、修复阻断问题和形成上线前结论，不得提前执行任务 20 的公网部署、购买服务或域名。

一、开始前

1. 完整阅读 `AGENTS.md`、`docs/project-status.md`、`docs/TODO.md`、`docs/decisions.md`、`docs/architecture.md`、`docs/requirements.md`、`docs/game-rules.md`、`docs/data-migrations.md` 和本提示词。

3. 确认 `main` 与 `origin/main` 同步。保留未跟踪的 `TIMEOFF.md`，不得修改、删除或提交。
4. 从最新 `main` 创建 `test/end-to-end`，在 `docs/project-status.md` 登记任务 19 进行中。
5. 先说明测试矩阵、环境方案、证据目录、缺陷分级和需要用户参与的步骤，再执行测试。

二、自动化与完整流程

1. 建立可重复运行的浏览器端到端测试，覆盖大厅、创建/短码加入、准备、开始、主动离房、分享链接、刷新恢复和连接替换。
2. 二、三、四人各完成至少一局真实 WebSocket 对局，覆盖出牌、压牌、过牌、收牌、补牌、轮转、普通空手和憋王；主 2 交换可使用可重复构造场景。
3. 覆盖三人双进攻游标及重新跟牌、四人固定队伍和旁观本轮权限。
4. 覆盖玩家/观战者聊天、限流、XSS 纯文本、100 条历史、跨房间隔离、观战加入/恢复/权威离开及容量释放。
5. 覆盖二至四人结算、SQLite 幂等写入、访客战绩、最近 20 局、写入失败重试及服务重启后历史查询。
6. 扫描 WebSocket 帧、DOM、localStorage、日志和数据库，确认没有对手手牌、完整牌墩、其他身份令牌或内部状态。

三、弱网与异常

1. 使用可重复的网络模拟测试延迟、抖动、短时离线、提交期间断线和恢复。
2. 验证倒计时由服务端权威推进；断线、恢复、聊天、观战加入和主 2 交换不得错误延长回合。
3. 覆盖响应丢失、重复请求、乱序/旧版本、旧连接关闭、新连接替换、玩家与观战者刷新。
4. 覆盖服务端优雅关闭、异常重启和 SQLite 重开。房间因当前内存架构在进程重启后丢失是已知限制，但历史记录不得丢失。
5. 评估长期断线玩家/观战者占位风险并给出建议；未经用户确认不得引入自动清退规则。

四、真实设备和响应式试玩

1. 检查桌面 1440×900、手机横屏 844×390、手机竖屏 390×844，截图保存在仓库外并报告绝对路径。
2. 若用户能提供同一局域网的另一台电脑或手机，必须给出从零开始的操作指引：如何启动、查看本机局域网 IP、手机打开哪个地址、如何创建/加入/观战。不要假设用户懂命令行。
3. 为真人朋友试玩准备简短清单和问题记录模板；不能虚构已经有真人参与。
4. 当前环境无法完成的跨物理设备项目必须明确列为“需要用户配合”，不能伪装成已验证。

五、缺陷、质量和证据

1. 缺陷按阻断、高、中、低分级，记录复现、根因、修复和回归证据。发现问题要在本分支修复并补自动化测试，不能只写报告。
2. 所有修复保持服务端权威、隐藏信息隔离和既定规则；规则歧义必须询问用户。
3. 运行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm test`、`pnpm test:coverage`、`pnpm build`、`git diff --check main...HEAD`。
4. 实际启动生产构建或等价环境，验证 `/health`、网页、WebSocket、SQLite 重开、控制台和进程清理。
5. 证据保存在仓库外稳定目录；仓库中只保存可维护测试、必要配置、缺陷报告和项目文档，不提交临时数据库、日志、浏览器配置或截图。
