# 永城八张运维手册

更新时间：2026-10-14

本文面向第一次维护网站的用户。预发布使用 Render 新加坡单实例和 Neon 新加坡 PostgreSQL；最终生产迁移到腾讯云中国大陆单实例和腾讯云 PostgreSQL。任何密码、数据库连接串、平台令牌和证书私钥都只能保存在平台的 Secret/环境变量管理中，不能发到聊天、截图或 GitHub。

## 架构与重启影响

浏览器通过同一个 HTTPS 地址加载网页，并用同域名的 WSS `/ws` 连接 Node.js 服务。Node.js 单实例保存等待房、进行中牌局、聊天、倒计时和重连会话；PostgreSQL 只保存已完成对局和访客战绩。

因此，应用发布、重启、休眠或故障会中断连接并清空所有进行中的房间，但已经成功写入 PostgreSQL 的历史战绩应继续存在。当前禁止将应用扩为两个实例；负载均衡会把玩家分到互不共享内存的进程。

连续房间赛、累计积分、当前倍率、继续投票和进行中的排名同样属于单实例内存状态。普通网络断开有 3 分钟恢复宽限，但应用重启不适用该宽限；发布前必须通知正在游戏的玩家。已完成单局写入 `games`，已结束整场汇总写入 `room_series`，二者应在重启后继续存在。

## 日常判断网站是否正常

依次检查：

1. 用无痕窗口打开公网首页，确认浏览器地址栏为 `https://` 且没有证书警告。
2. 打开 `https://公网地址/health`，应看到 `{"status":"ok"}`。这表示 Node.js 进程存活。
3. 打开 `https://公网地址/ready`，应看到 `{"status":"ready"}`。这表示数据库也可访问；若返回 HTTP 503，先检查数据库。
4. 在首页创建测试房间，再用另一个无痕窗口加入。能实时看到座位变化表示 WSS 正常。
5. 平台 Metrics 中 CPU、内存、出站流量和重启次数不应持续异常升高。

免费 Render 实例空闲后首次打开可能等待约一分钟；正式付费环境不应有这种休眠。

## 查看错误日志

Render：打开 Dashboard，点击 `8cards-preview`，点击左侧 **Logs**。腾讯云：先看轻量服务器监控，再通过受控终端查看容器日志。

日志是单行 JSON，重点搜索：

- `startup_failed`：环境变量、迁移或数据库连接失败；
- `uncaught_exception` / `unhandled_rejection`：未处理程序错误；
- `shutdown_timeout`：进程未能在 25 秒内退出；
- 平台的 OOM、exit 137：内存不足；
- 频繁 `server_started`：实例反复重启。

日志不得出现 `DATABASE_URL` 的真实值、密码、重连令牌、手牌或牌墩。发现秘密后立即停止公开服务、轮换秘密并检查 Git 历史，不能只删除一条日志。

## 查看数据库容量和连接

Neon：打开项目，进入 **Monitoring** 或 **Usage**，查看 Storage、Compute、Data transfer 和连接数。腾讯云：打开云数据库 PostgreSQL 实例，查看 **监控告警**、存储使用率、连接数和备份空间。

可在受信任的数据库控制台执行只读查询：

```sql
SELECT pg_size_pretty(pg_database_size(current_database())) AS database_size;
SELECT count(*) AS active_connections FROM pg_stat_activity;
SELECT count(*) AS games FROM games;
```

存储达到套餐的 70% 时先导出备份并调查增长；不要直接删除历史。

## 手动备份

备份文件包含玩家昵称和历史记录，应当视为敏感数据。不要提交 Git，也不要放在公开网盘。

在已经安全设置 `DATABASE_URL` 的服务器或临时运维容器中执行：

```sh
BACKUP_DIR=/安全备份目录 sh scripts/backup-postgres.sh
```

脚本使用 PostgreSQL custom 格式，权限为仅当前用户可读，并输出生成文件路径。每次迁移或正式发布前备份一次；正式生产至少每周做一次外部逻辑备份，并保留最近 4 份。平台自动快照不能替代离开平台保存的逻辑备份。

备份完成后检查文件大小不为零，并运行：

```sh
pg_restore --list /安全备份目录/8cards-时间.dump
```

## 恢复演练

永远先恢复到全新的空白测试数据库，不要直接覆盖生产库。

1. 创建临时测试数据库。
2. 把终端的 `DATABASE_URL` 指向该测试库；不要把连接串粘贴到聊天。
3. 再三确认主机名和数据库名不是生产库。
4. 执行：

```sh
RESTORE_CONFIRM=RESTORE_8CARDS_DATABASE sh scripts/restore-postgres.sh /安全备份目录/8cards-时间.dump
```

5. 用只读 SQL 核对 `schema_migrations`、`games`、`game_visitors` 数量。
6. 临时连接应用并查询一位测试访客的历史。
7. 验收后删除临时测试数据库。

真正灾难恢复时也先恢复为新库，确认数据后再把应用的 `DATABASE_URL` 切换到新库。切换会重启应用并清空进行中的房间，应提前通知玩家。

## 发布新版本

1. 确认任务分支全部检查通过且备份完成。
2. 记录当前健康版本的 Git 提交 SHA 和平台部署 ID。
3. 将经过总控验收的提交合并并推送；不要直接在服务器改代码。
4. 在 Render 手动选择 **Deploy latest commit**；腾讯云生产按已记录的镜像标签部署。
5. 观察构建日志，迁移失败时新版本不得接管流量。
6. 部署完成后依次检查 `/health`、`/ready`、HTTPS、WSS、创建/加入和历史。
7. 至少观察 15 分钟的错误、重启、CPU、内存和数据库连接。

`render.yaml` 已关闭自动部署，避免一次普通 Git 推送直接影响玩家。

## 回滚失败版本

应用代码回滚与数据库恢复是两件事。迁移必须向前兼容，通常只回滚应用，不回滚数据库。

Render：进入服务 **Deploys**，找到之前通过验收的部署，选择 **Redeploy**。腾讯云：重新部署上一个已知良好的不可变镜像标签。随后检查 `/health`、`/ready` 和 WSS。

只有确认数据库数据损坏时才执行数据库恢复；先恢复到新数据库再切换连接串。不要在慌乱时对生产库直接运行 `pg_restore --clean`。

## 修改环境变量

1. 在平台服务的 **Environment** 页面修改，不编辑仓库文件。
2. 密钥类变量使用 Secret 类型。
3. 保存前截图时遮住值；不要把值发到聊天。
4. 修改会触发重启，先告知正在游戏的玩家。
5. 重启后检查 `/ready` 和历史记录。

变量清单：

| 变量 | 是否秘密 | 作用 |
| --- | --- | --- |
| `NODE_ENV` | 否 | 正式环境固定为 `production` |
| `PORT` | 否 | 平台注入监听端口 |
| `HOST` | 否 | 固定 `0.0.0.0` |
| `DATABASE_URL` | 是 | PostgreSQL 连接串 |
| `PUBLIC_BASE_URL` | 否 | 完整公网 HTTPS 地址，无尾部 `/` |
| `TRUSTED_ORIGINS` | 否 | 允许连接 WSS 的精确来源，通常等于公网地址 |
| `SHUTDOWN_TIMEOUT_MS` | 否 | 优雅关闭上限，默认 25000 |
| `STATIC_DIR` | 否 | 容器内网页产物目录 |
| `EIGHTCARDS_MIGRATIONS_DIR` | 否 | 容器内迁移目录 |
| `EIGHTCARDS_DB` | 否 | 仅本地 SQLite；不能与 `DATABASE_URL` 同设 |

## 查看费用与额度

Render 每周查看 Billing 的实例小时、5 GB 出站流量和 500 分钟构建额度；Neon 查看 1 GB 数据库、100 CU-hours 和 5 GB 传输。免费预发布不绑定付款方式。腾讯云购买前关闭自动续费或明确设置余额/费用告警，分别核对首购价和续费价。

达到额度 70% 时记录原因；达到 85% 时暂停非必要试玩；不要为解除限制而直接点击升级。

## 域名、HTTPS 和 WSS 故障

- HTTPS 证书错误：检查域名解析、证书绑定、证书有效期和服务器时间。
- HTTPS 正常但 WSS 失败：浏览器开发者工具查看 `/ws`，确认使用 `wss://`，Nginx 保留 `Upgrade` 与 `Connection` 头，`TRUSTED_ORIGINS` 精确匹配网页源。
- 403：通常是可信来源不匹配。
- 502/503：检查容器、`/health`、`/ready` 和数据库。
- 只有部分中国网络失败：分别用移动、联通、电信测试 DNS 和链路，不要先改游戏代码。

Render 和最终腾讯云都应让浏览器只访问一个 HTTPS 域名，避免 HTTPS 页面连接明文 `ws://`。

## 紧急停止服务和导出数据

1. 在平台暂停应用服务或将入口切到维护页；不要先删除服务。
2. 保持 PostgreSQL 运行，立即生成逻辑备份。
3. 下载并验证备份清单，把文件保存到两个受控位置。
4. 记录应用提交 SHA、部署 ID、数据库实例、事件时间和错误日志。
5. 确认备份可恢复后，才考虑释放付费资源。

删除数据库、域名或云账号属于不可逆操作，必须另行确认。暂停应用会立即断开玩家并丢失进行中房间，但不会删除 PostgreSQL 历史。
